# GrassKickZ product standard

## Shared context and source freshness

- Start with `TEAM_HANDOFF.md` and the paired backend's `docs/TEAM_CURRENT_STATE.md` and `docs/TEAM_WORKFLOW.md`.
- Check the actual branch, commit, local changes and fetched upstream in both repositories before relying on old chat context. Preserve local work; do not blindly reset or pull a dirty checkout.
- Close tasks with source commits, verification, remaining work and deployment status. GitHub source and the running deployment are separate records.

- Primary review and demonstration context: use `coach@talanti.ge` and **FC Dinamo Tbilisi Academy** first. This is the user's everyday account and club. Keep Riverside and other accounts for additional role, permission and cross-club checks; do not substitute them for the main usability review.

- Simplify everyday work without removing usefulness. Keep one stable workspace across a person's approved responsibilities; use task and squad context rather than forcing role modes. Keep advanced tools discoverable in predictable places. Self-requested role or access changes require club leadership approval before taking effect.

- Deploy functional changes to the existing live demo as part of completion, unless the user says otherwise, with appropriate release checks and backup/migration safeguards. Pure UI/UX-only work may remain local unless publication is requested.

- Build for the quality expected by UEFA: credible football data, coherent workflows, accessibility, privacy, polished responsive design, and clear language. This is an ambition, not a claim of UEFA approval or affiliation.
- Public football identity is separate from account permissions and organization ownership. Support several roles per person.
- Players, coaches, referees, agents, and club/academy staff need professional profiles with relevant careers and qualifications. Fans, parents, and non-club organization owners/managers use simpler profiles unless they also hold a professional football role.
- Distinguish self-reported credentials from recorded appointments and verified facts. Never invent careers or accreditation.
- Agent Dola can guide complicated workflows; do not remove necessary functionality just to simplify a page.
- Preserve existing work and use focused verification. Work directly with the selected model, without Jev model routing or subagents unless the user explicitly requests delegation. Follow frontend/AGENTS.md for work in that application.
